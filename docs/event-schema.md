# Event schema (v1)

The contract between the ingester (`ingester/`) and the API (`api/`).

**Model:** clients append immutable, timestamped *facts* about the car they are driving. The server stores them unchanged in an append-only `events` table and *derives* sessions, stints, pit stops and laps from them. Clients hold no server IDs and never update anything.

## Delivery guarantees

- **At-least-once.** The client keeps events in a local, on-disk outbox and resends until the server acknowledges them. Duplicates are expected.
- **Idempotent ingest.** Every event carries a client-generated `event_id` (UUID). The server ignores an `event_id` it already has, so resending is always safe.
- **Order-independent.** Events may arrive late or out of order, and from several clients for the same car. The server orders them by `session_time` and re-derives the whole car each time new events arrive. Derivation must give the same result regardless of arrival order.

## Who sends what

- **Car events** (everything below except `session_info` and `race_started`) are sent only by the client whose user is **currently driving** the car. That is the only client that sees the car's telemetry.
- **Session-level events** (`session_info`, `race_started`) may be sent by any client in the session. The server keeps the first one it sees and treats the rest as duplicates.
- A driver swap is not a special protocol. Driver A's client sends `driver_exited`, driver B's client sends `driver_entered`, and the server sees both on one timeline.

## Envelope (every event)

| Field | Type | Notes |
|---|---|---|
| `schema_version` | int | `1` |
| `event_id` | uuid | Generated by the client when the event is created. Used for deduplication. |
| `type` | string | One of the types below. |
| `session_id` | int | iRacing `WeekendInfo.SubSessionID`. |
| `car_idx` | int | iRacing `CarIdx` of the team car. Stable within a subsession. |
| `session_num` | int | iRacing `SessionNum` (race session within the event). |
| `session_time` | float | iRacing `SessionTime`, seconds. **The ordering key.** It is the same clock on every client in the session. |
| `session_tick` | int | iRacing `SessionTick`. Tie-breaker for events at the same `session_time`. |
| `driver` | object | The user who sent the event: `{ "user_id": int, "name": string }`. Taken from the `DriverInfo.Drivers` entry whose `UserID == DriverInfo.DriverUserID`, **not** from the array position. |
| `client` | object | `{ "install_id": uuid, "app_version": string }`. For debugging only. |
| `sent_at_utc` | datetime | Wall clock when the event was created. For debugging only. |
| `payload` | object | Type-specific fields, listed below. |

## Event types

### `session_info` (session-level)
Sent once per client per session: at race start, or on the first race tick if the app starts mid-race. The server uses it to fill `sessions` and `session_cars`.

`track`, `car_name`, `car_class` (falls back to `car_name` if empty), `team_id`, `team_name`, `car_number`, `race_duration_s` (parsed from `SessionInfo.Sessions[session_num].SessionTime`), `session_date` (the client's local date).

### `race_started` (session-level)
Sent when the session state first becomes `Racing`. No payload.

### `driver_entered`
Sent when this user becomes the driver: at race start if already in the car, when the app starts while the user is driving, or when the user takes over after a swap.

`car_state`, `conditions`, `on_pit_road` (bool), `in_pit_box` (bool).

`on_pit_road` and `in_pit_box` are what make a mid-stop swap unambiguous: if `in_pit_box` is true, this driver joined a pit stop that is already in progress. The client must also **seed its own edge-detection state** (`wasOnPitRoad`, `wasInPitBox`) from these values, so it doesn't emit false `pit_road_entered` or `pit_box_entered` events on its first tick.

### `driver_exited`
Sent when this user stops being the driver.

`car_state` and `conditions` from the **last tick while driving** (the telemetry may already be gone on the exit tick), plus `on_pit_road` and `in_pit_box` from that same last tick.

### `pit_road_entered`
`car_state`, `via_tow` (bool; true when it was triggered by `PlayerCarTowTime > 0`).

### `pit_box_entered`
`car_state`, `required_repair_s` (`PitRepairLeft`), `optional_repair_s` (`PitOptRepairLeft`), `fast_repair_available` (`FastRepairAvailable`), and `tires_requested`: `{ lf, rf, lr, rr }` (bools from `dp??TireChange > 0`).

A tire marked here is guaranteed to be changed, so `tires_requested` is treated as "tires changed".

### `pit_box_exited`
`car_state`, `conditions`. The conditions are needed because a new stint starts here.

### `pit_road_exited`
`car_state`.

### `lap_completed`
Emitted after the existing `LapTickDelay`, so the lap time is valid.

`lap_number` (`LapCompleted`), `lap_time` (`LapLastLapTime`; may be ≤ 0 when iRacing invalidates it), `car_state`.

### `race_finished`
Sent when this car takes the checkered flag, using the existing `RaceHasEnded()` logic.

`car_state`, `on_pit_road` (bool).

### `car_status` (periodic)
Sent every N seconds while driving (default 10 s, configurable in the client). It feeds the live race tool, and gives a last-known state when a client dies without sending `driver_exited`.

`car_state`, `on_pit_road`, `in_pit_box`.

## Derivation rules (server)

All rules apply per `(session_id, car_idx)` over events sorted by `(session_time, session_tick)`.

**Stint**
- **Starts** at:
  - `pit_box_exited`;
  - `driver_entered` with `on_pit_road == false`;
  - `driver_entered` on pit road but not in the box, with no stop in progress (a pit lane start);
  - `race_started`, if a `driver_entered` came before it.
- **Ends** at:
  - `pit_box_entered`;
  - `driver_exited` with `in_pit_box == false`;
  - `race_finished`.
- **Driver:** taken from the event that started the stint.
- **Start/end values:** fuel, position and incidents come from the start and end events' `car_state`. Conditions come from the start event.
- **Open stints:** a stint with no end is shown as *open* while the race is live. Once `race_finished` is seen, or the session is over, it is closed at the last known `car_state` (`car_status` or `lap_completed`) and marked `ended_abnormally`.

**Pit stop**
- **Starts** at `pit_road_entered`, or at `pit_box_entered` if no road entry was seen.
- **Ends** at `pit_road_exited`.
- **Service window:** from the first `pit_box_entered` to the last `pit_box_exited` inside the stop.
- **Fuel:** `fuel_start` comes from the `pit_box_entered` event; `fuel_end` from the `pit_box_exited` event.
- **Driver swap:** a `driver_exited` followed by a `driver_entered` inside the stop is recorded as a swap (`from_driver`, `to_driver`).
- **Stop status:** `complete`; `open` (no exit yet); or `abandoned` (a new `pit_road_entered` or `race_finished` arrived with no exit).
- **Drive-throughs:** a pit road visit with **no** `pit_box_entered` (a drive-through penalty, an aborted stop, or driving through pit lane) is **not** a pit stop. It is recorded separately as a `drive_through` with its road window only. It does not end the stint, and it is excluded from pit stop counts and service-time reports.
  - Because a visit can't be classified until it ends, an open pit road visit is reported as *in pit lane* (for the live tool). It becomes a pit stop as soon as a `pit_box_entered` arrives, or a drive-through when `pit_road_exited` arrives with no box entry.

**Lap**
- One lap per `lap_number`. A duplicate keeps the first one by `session_time`.
- The lap's stint is the stint whose time window contains the lap's `session_time`.
- `lap_time ≤ 0` is stored as null. Reports may derive the time from the previous lap's `session_time`.

## Ingest API

`POST /v1/events` with body `{ "events": [ ... ] }`, up to 100 events per call, authenticated with the existing `X-API-Key` header.

- **Response:** `200` with `{ "accepted": [ids], "duplicates": [ids], "rejected": [{ "id", "reason" }] }`.
  - A rejected event (fails validation) is not retried; the client logs it and drops it.
  - Anything else not acknowledged (timeout, 5xx) stays in the outbox.
- **Storage:** `events` table with an `id` primary key, `event_id` unique, envelope columns, and `payload` as JSONB, stored exactly as received.
- **Derivation is on read (v1).** `GET /v1/sessions/{session_id}/cars/{car_idx}/timeline` derives stints, pit stops, drive-throughs, laps and a live state from the car's events each time it is called. That is a few hundred events per car, so it's cheap. Materialized derived tables can be added later (for example for SQL access from dashboards) without changing the contract, because they are rebuildable from `events`.
- **Debugging:** `GET /v1/sessions/{session_id}/cars/{car_idx}/events` returns a car's raw events in session-time order.

## Decisions

1. **Stint definition.** A stint is the time spent driving between the race start (or the end of one pit stop) and the start of the next pit stop. Every pit stop ends a stint, even if the same driver continues.
   - The boundaries are the **pit box** edges, as in the current code: a stint ends at `pit_box_entered` and the next one starts at `pit_box_exited`.
   - Driving down pit lane therefore counts toward the stints, so it overlaps the pit stop's road window (`pit_road_entered` → `pit_road_exited`). This is intended. Report the pit stop's *service time* (box window) and *total pit lane time* (road window) separately.
   - Splitting at the box (not at pit road) means a drive-through or other pit lane visit without stopping never splits a stint. A driver swap always happens in the box, so every stint belongs to exactly one driver.
2. **`car_status`** is in v1, at a default of 10 s. The rate is a client setting, so it can be changed if usage grows past the current 4–5 concurrent users.
3. **Spectating teammates** send only `session_info` and `race_started`. Nothing per-car in v1.
4. **Tire changes.** A tire marked for change at `pit_box_entered` is guaranteed to be changed. `tires_requested` is treated as "tires changed".
